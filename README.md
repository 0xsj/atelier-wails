# atelier-wails

Initial Wails 2 / Go scaffold for the Atelier workbench template family.
The sibling builds are independently usable; this repository imports no sibling.

Svelte 5 + TypeScript + Vite renders the component kitchen sink as the working
screen. The frontend foundation includes layered semantic tokens, light/dark/system
themes, desktop density tokens and Bits UI as an unstyled interaction dependency.
On top of that sits a component library (primitives, layout, forms, feedback,
navigation, overlays, collections, data display, content utilities and patterns)
and the workbench UI slice: shell with title bar and activity rail, stacked
sidebar panes, split editor groups with document tabs, quick pick and command palette,
save-changes and confirmation dialogs, and status bar. The workbench model layer (views, layout, snapshot, commands, keybindings)
and app layer (store, command dispatch, keybinding scopes, navigation history,
restoration port) are implemented as TypeScript with vitest tests, and the
gallery's workbench demo runs on them, with native restoration stored as an
atomically replaced `workbench.json` document beside Preferences. The Preferences round
trip is wired end to end: a frontend kernel (Result, closed failure kinds,
presence, identity), total wire codecs, a preferences service with
compare-and-replace and reconcile, a Wails desktop adapter, an in-memory
preview adapter for the browser, and a preferences feature that persists the
gallery's theme and density through the native store, plus a preview-only
WorkspacePicker over the registry contract. Native Workspace transport and
Jobs remain reserved. Native startup is split into entry, composition root and
host.
Candidate contexts are scaffolded with ownership notes and revision 1 contracts;
see [DOMAIN_CONTRACTS.md](DOMAIN_CONTRACTS.md) and [FOUNDATION.md](FOUNDATION.md).

The earlier [architecture proposal](ARCHITECTURE.proposed.md) records the design
discussion; the current frontend groups reusable modules under `src/lib` (under
`frontend/` in Wails). UI framework selection is now settled as Svelte.

## Setup

Use the Node version in `frontend/.nvmrc` and the Go version in `go.mod`.
Install native prerequisites for your OS using the
[Wails guide](https://v2.wails.io/docs/gettingstarted/installation/).

```sh
make install
```

Wails is pinned as a Go tool dependency: `go tool wails` works without a global
CLI installation. The existing github.com/0xsj/atelier-wails module identity is
preserved. go.sum verifies module downloads; frontend/package-lock.json pins
frontend tools.

## Run

```sh
make dev
```

For the static frontend alone: `make frontend` at http://127.0.0.1:1422.
A browser preview does not start the Go host.

## Check and build

```sh
make check
make test-browser
make build
```

Desktop builds target the current host platform and produce output in build/bin.
`make check` also runs the vitest suite for the pure workbench models and app
layer; `make test-browser` runs the rendered Svelte contracts in Chromium. The
rest verifies types, the build and the toolchain.

## Layout

```text
main.go           thin Go entry; root/ composes internal/host/wails
frontend/src/     Svelte entry, dev/gallery kitchen sink and lib/ frontend library
frontend/dist/    built frontend assets embedded by Go
wails.json        desktop and frontend build configuration
build/            native packaging files generated by Wails
```

Keep the generated native packaging files when customizing application metadata
later. The initial identity and icons are development placeholders.

## Bootstrap verification

Verified on macOS arm64, 2026-09-11: frontend typecheck and production build;
Go vet; Wails production app compilation, packaging and local self-signing.
The Hello world native window was launched with `make dev` and its text verified
through macOS accessibility on 2026-09-11. No cross-platform release validation is claimed.
The Go 1.27.1 linker emitted a macOS deployment-target warning (13.0 object, 11.0
link target); the minimum supported macOS version remains a brief/release decision.

## Frontend verification

On 2026-09-14 the frontend type check, 82 unit tests, 4 rendered browser tests
and production build pass with the full component library and gallery. The
workbench restoration port now uses an in-memory document in browser previews
and the native file-backed document in Wails. The browser suite covers
representative DOM semantics, shell landmarks, click handling and activity
keyboard navigation; broad visual and native-window interaction remains
unverified. See [verification evidence](notes/svelte-foundation-verification.md)
for exact commands, results and limitations. The Workspace picker currently
uses an in-memory preview registry; native Workspace transport and Jobs remain
reserved.
